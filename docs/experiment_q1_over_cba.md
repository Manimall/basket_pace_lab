# Эксперимент: Q1 Over в CBA на топ-pace командах

**Статус:** NEXT / not started
**Автор гипотезы:** Maksim
**Тип:** probe → (если подтвердится) сбор данных + валидация

---

## 1. Гипотеза

Матчевый тотал в CBA бук выставляет корректно (лига-скорофест, данных много, линия efficient — пробить её на дистанции нельзя). **Эдж — не в уровне скоринга, а в кривом распределении линии по четвертям:** буки дробят четвертные/half-линии лениво (≈ `game_total / 4` с косметикой) и не моделируют, что реальный **темп Q1 систематически выше** этой наивной доли, особенно когда обе команды быстро стартуют.

**Проверяемое утверждение:** в матчах, где **обе** команды в топ-квартиле по Q1-pace (point-in-time, внутри сезона), фактический комбинированный счёт Q1 систематически превышает наивную Q1-линию `total_line / 4`.

**Контроль (обязателен):** тот же тест для **Q4** должен показать, что garbage time / фолы / сушка при отрыве убивают эдж → это подтверждает механизм, а не случайный оверфит.

## 2. КРИТИЧЕСКАЯ находка по данным (определяет структуру задачи)

В схеме (`src/database/models.py`) **нет поля Q1-линии**:
- `Match.total_line` — closing O/U на матч ✅
- `Match.total_line_open` — opening на матч ✅
- `Match.first_half_line`, `Match.second_half_line` ✅
- **`first_quarter_line` — ОТСУТСТВУЕТ** ❌

Поэтому эксперимент двухфазный:

- **Phase 1 (без нового скрейпинга):** тестируем перекос против **прокси-линии** `total_line / 4`. Это меряет НЕ «эдж против бука», а «долю Q1 в матче». Если фактический Q1 даже не выше `total_line/4` систематически — жилы нет, дальше не идём. Дешёвый kill-switch.
- **Phase 2 (только если Phase 1 зелёная):** добавить сбор **реальной Q1-линии** в коллектор → мерить настоящий edge/CLV/ROI против закрытия.

## 3. Какие поля тянуть

### Из `Match`
| Поле | Зачем |
|---|---|
| `id`, `flashscore_match_id`, `league_id`, `season`, `start_time` | ключи, point-in-time сортировка |
| `total_line` | база для прокси Q1-линии (`/4`) |
| `has_quarter_breakdown` | **фильтр:** брать только `True` (иначе Q1 нет) |
| `went_to_overtime`, `overtime_periods_count` | контроль OT-контаминации в матчевых агрегатах |

### Из `QuarterStats` (одна строка на команду на период)
| Поле | Зачем |
|---|---|
| `match_id`, `period_number`, `period_type` | **фильтр:** `period_type = 'quarter'` И `period_number = 1` для Q1 |
| `home_score`, `away_score` | комбинированный Q1 = сумма по обеим командам за период 1 |
| `q4_includes_ot_points` | **фильтр для Q4-контроля:** исключать строки `True` (OT смешан в Q4) |

**Q1 combined points** = `home_score + away_score` для строки с `period_number=1, period_type='quarter'`.

## 4. Как считать Q1-pace-квартиль (point-in-time, без утечки)

`Q1-pace` тут — **прокси через очки**, а не строгие владения (per-quarter possessions в схеме нет). Для каждой команды:

1. `q1_pf` = очки, набранные командой **в Q1** (её сторона счёта в period 1).
2. `q1_pace_proxy_team` = скользящее среднее `q1_pf` за **предыдущие N игр этого же сезона** (по умолчанию **N = 5**, вынести в параметр).
3. **Строго point-in-time:** в расчёт квартиля для матча берём **только игры до `start_time` этого матча**. Никаких будущих игр.
4. **Никакого cross-season переноса** — окно обнуляется в начале сезона (см. урок [[nba-walk-forward-mirage]]: within-season сигнал не пережил cross-season, −7.5%, CI95 весь ниже нуля — тот же риск здесь).
5. Порог eligibility: у команды должно быть **≥ N прошлых игр в сезоне**, иначе матч выпадает из выборки.
6. **Top-quartile** = команды, у кого `q1_pace_proxy_team` в верхних 25% распределения лиги **на момент этого матча** (пересчитывать квантиль на каждую дату, не глобально по всему датасету — иначе утечка).

**Критерий отбора ставки:** обе команды матча в топ-квартиле Q1-pace → сигнал `Q1 Over`.

## 5. Метрики и валидация

- **Первичная:** `mean(q1_combined_actual − q1_line_proxy)` в очках + **95% CI блочным бутстрапом по датам** (не по матчам — учесть корреляцию внутри тура/дня).
- **Hit rate** `Over` против прокси-линии; **ROI** при −110 (Phase 1 — иллюстративно; Phase 2 — по реальным Q1-коэффам).
- **Walk-forward / cross-season** обязателен (паттерн из `scripts/blind_threshold_validation.py` и `src/models/validate_by_league.py`): отобрать порог на сезонах `[t..t]`, проверить на `t+1`. Если эдж живёт только in-sample — это мираж, закрываем.
- **Q4-контроль:** прогнать тот же пайплайн на `period_number=4` (с фильтром `q4_includes_ot_points=False`). Ожидание: CI95 накрывает ноль / отрицательный. Если Q4 «тоже жила» — скорее оверфит/баг, а не сигнал.

## 7. Готчи (не наступить повторно)

- **Numeric `external_id` filter** — фильтр лиги по числовому `external_id`, не по строке (известная ловушка пайплайна).
- **`period_type='game'` требует odds** — game-level fallback-строки идут только там, где есть коэффы; для Q1 нужен `has_quarter_breakdown=True`.
- **Нет `first_quarter_line` в БД** — Phase 1 только на прокси `total_line/4`; реальный edge мерить нельзя до Phase 2.
- **OT-контаминация** — для матчевых агрегатов брать regulation-only; для Q4 исключать `q4_includes_ot_points=True`. Q1 от OT не страдает.
- **Утечка в квантиле** — квартиль пересчитывать на дату матча, не по всему датасету.
